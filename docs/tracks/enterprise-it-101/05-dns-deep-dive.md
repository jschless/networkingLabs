## Containers

| Name | Image | IP | Role |
|------|-------|----|------|
| `dns1` | `ubuntu/bind9:latest` | `10.100.1.40` | Recursive resolver + conditional forwarder |

## What is Pre-Built

- BIND9 installed and running with an empty config
- Samba DNS on `dc1` already authoritative for `lab.corp`

## What You Configure

**1. Recursive resolver for internet queries**

In `/etc/bind/named.conf.options`:
```
options {
    recursion yes;
    allow-recursion { 10.100.0.0/16; };
    forwarders { 8.8.8.8; 1.1.1.1; };
};
```

**2. Conditional forwarder for lab.corp**

```
zone "lab.corp" {
    type forward;
    forwarders { 10.100.1.10; };   // dc1
};
```

**3. Split-horizon for apps.lab.corp**

Create internal and external views serving different answers for the same name:
```
view "internal" {
    match-clients { 10.100.0.0/16; };
    zone "apps.lab.corp" {
        type master;
        file "/etc/bind/db.apps-internal";   // portal → 10.100.2.50
    };
};

view "external" {
    match-clients { any; };
    zone "apps.lab.corp" {
        type master;
        file "/etc/bind/db.apps-external";   // portal → 203.0.113.50
    };
};
```

**4. Switch workstations to use dns1**

Update `/etc/resolv.conf` on `ws1` and `ws2`:
```
nameserver 10.100.1.40
```

**5. Add a reverse zone for 10.100.1.0/24**

```
zone "1.100.10.in-addr.arpa" {
    type master;
    file "/etc/bind/db.reverse-1";
};
```

## Verification Commands

```bash
# Recursive resolution through dns1
dig @10.100.1.40 google.com A +short

# Conditional forward to AD
dig @10.100.1.40 _ldap._tcp.lab.corp SRV
dig @10.100.1.40 dc1.lab.corp A

# Split-horizon (from inside the lab network)
dig @10.100.1.40 portal.apps.lab.corp A   # expect 10.100.2.50

# Reverse DNS
dig @10.100.1.40 -x 10.100.1.10          # expect dc1.lab.corp

# Full resolution trace
dig @10.100.1.40 google.com +trace
```

## What This Lab Teaches

- Enterprise DNS is **layered**: AD DNS handles the domain; BIND handles everything else
- **Conditional forwarding** glues AD DNS into a larger DNS hierarchy
- **Split-horizon** serves different answers to internal vs. external clients
- **Reverse DNS (PTR)** matters for mail delivery, logging, and troubleshooting
- `dig +trace` shows the full resolution chain — essential for debugging

## Experiments

- Break the conditional forwarder and watch domain logins fail (they depend on DNS SRV records)
- Enable BIND query logging and trace every DNS query generated by a domain join
- Create a CNAME loop and observe the behavior
- Add response rate limiting (RRL) to BIND and test its effect
